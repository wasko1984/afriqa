AFRIQA: from problem to next steps

One input, one AI request, one structured plan. AFRIQA interprets the problem's domain and produces possible causes, explained urgency, three actions and Days 1–7 with progress checks.

  1. 1. Describe and submit →components/problem-form.tsx
    The generate function validates input and sends it to POST /api/plan. Retry retains the original submitted problem.
  2. 2. Generate and validate →lib/plan-prompt.ts shapes domain-specific instructions. lib/gemini.ts calls Gemini. lib/plan-schema.ts checks the JSON response before it can succeed.
  3. 3. Read the resultcomponents/plan-provider.tsx holds the active plan in memory. components/plan-view.tsx displays its domain, actions and timeline at /results.

Reference route: structured AI output

This is a reference route, not a record of an interactive code tour.

  1. lib/plan-prompt.ts → buildPrompt: identify the central domain, keep every section relevant, respect resources and prioritize immediate help when needed.
  2. lib/plan-schema.ts → planSchema / planJsonSchema: the provider schema guides generation; runtime validation requires a recognized domain, exactly three actions and ordered Days 1–7.
  3. lib/gemini.ts → generatePlan: extract and parse a completed AI response. app/api/plan/route.ts → POST returns only validated plans, otherwise a recoverable error.

To change this, start here

  • Advice and domain behavior: lib/plan-prompt.ts; repeat the real scenarios in devpost/domain-verification.md.
  • Required output fields: lib/plan-schema.ts; update tests/fixtures.ts and consumers, then run schema and browser tests.
  • Result wording and layout: components/plan-view.tsx and app/globals.css.
  • Input or Retry: components/problem-form.tsx; verify tests/workflow.spec.ts.

A practice to reuse

Turn a requirement into an observable check. The domain requirement became a schema rejection/preservation test in tests/plan-schema.test.ts and a visible perspective check in tests/workflow.spec.ts. Real scenarios then revealed a distracting shop task in a health emergency, despite valid JSON. That led to a refined prompt and another real request.

Use both structural tests and real content review on future AI projects. Valid JSON does not establish correct advice, diagnosis or classification. Keep an error visible rather than inventing a successful result.

Run it again

Use Node.js 22. Run npm install, configure .env.local from the secret-free .env.example, and run npm run dev. Open http://localhost:3000. AI generation requires internet and available Gemini quota.

Checks: npm test, npm run typecheck, npm run lint, npm run build, and npm run test:e2e after browser setup in the README.

There is no database or saved history. Refreshing results clears the in-memory plan. The API key stays on the server. This map works offline with scripts disabled; the app's AI feature requires internet. It is a source snapshot and can drift after changes.
